# 视频帧所有权与关闭同步参考版

这里只提供完整参考文件，没有覆盖Components中的业务文件。

替换对应的Svc_Video.h、Svc_Video.c、App_Cloud_Upload.c、App_Video_Streaming.c。第一次初始化仍必须放在app_main创建视频和上传任务之前，并检查返回值：

```c
ESP_ERROR_CHECK(Svc_Video_Init());
```

接口变化：Init、Deinit、Reset现在返回esp_err_t。原先的Svc_Buf_pool_Init/Deinit改为Svc内部私有函数，应用不直接调用。两个同步对象在第一次Init时创建，Deinit后保留，避免等待中的任务访问已删除的锁。

采用当前工程的一个采集任务、一个上传任务模型。同一帧只能由成功Hold它的任务Release。不能把指针再交给异步后台使用后就立即Release；使用完成才能释放。当前MQTT publish调用按现有同步调用方式使用。

- state_lock只保护状态、帧借用登记和非阻塞队列操作。
- io_lock串行化摄像头操作与Init/Close/Reset/Deinit，防止摄像头正在取帧时释放驱动资源。
- 获取顺序为io_lock→state_lock；Hold/Release只获取state_lock。
- Hold在Svc内部以10ms步长轮询非阻塞队列，不会在待销毁的队列上永久阻塞。
- 关闭时停止接纳新Hold，等待原所有者Release；不会替其他任务归还帧。
- 取得io_lock最多等待2秒；取得后，等待持帧任务归还最多2秒。这两个等待阶段分别计时。
- 超时返回错误并保留队列/帧内存。原所有者仍能Release，随后可重试关闭。
- 普通Stop暂停采集，保留已就绪的数据；Ctrl(video_off)完成关闭并清掉待上传的旧帧。
- Deinit销毁帧池；Reset保留帧池并重新初始化摄像头，随后仍需Ctrl(video_on)。

验证：使用缓存的目标SDK配置和原编译参数，参考版Svc_Video.c、两个App文件以及原main共4个C文件交叉编译通过。14项主机线程/模拟驱动检查全部通过，详情见tests.json和cross-compile.json。没有完整重链接、烧录或真实FreeRTOS/硬件测试。

范围限制：本版处理帧所有权、队列生命周期与摄像头操作串行化。原BSP部分初始化失败回滚、实际映射长度和硬件驱动行为没有在这里重写。原Base64编码边界、MQTT事件字段读取、Wi-Fi重连等其他已知问题仍须分别处理。App上传函数保留了现有编码/发布调用，不能据此将整个项目标记为稳定完成。

Release失败会触发App中的ESP_ERROR_CHECK。按本版单所有者和队列数量守恒的约定，正常路径不应失败；这是资源所有权约定遭到破坏时的显式故障处理。
