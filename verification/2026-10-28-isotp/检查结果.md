# 视频与 CAN 同时运行时的 ISO-TP 联调修订

日期：2026-10-28。

## 触发条件与结论范围

用户报告：启动摄像头传输后 ISO-TP 不再取得完整数据，复位两块板后才可能恢复。实际使用工程为 D:/ProgramData/codex/test_9_29_zhi_neng_jia_ju。

代码检查未发现默认 CAN TX/RX GPIO 3/10 与默认摄像头 DVP 引脚直接重叠。没有执行板上测量，尚不能认定视频开启时的最终故障源。

已确认的集成问题：

1. 原 esp_isotp 0.1.1 适配将栈上的 twai_frame_t 和协议临时数据交给异步驱动；ESP-IDF 6.0.1 驱动保留指针、忙时仅排队指针，因此存在确定的发送生命周期错误。
2. 原接收中断直接修改 IsoTpLink，任务同时调用 poll/receive，没有状态串行化保护。
3. 业务传感器队列入队被改成等待 100 tick；默认 tick 为 1 ms，而 ISO-TP 超时为 100 ms，队列满时会拖延轮询。此项是延迟风险，不是已经证明的上板触发原因。
4. 原 bus-off 检查函数会删除 CAN 节点而保留 ISO-TP 句柄，且没有被正常轮询路径调用。现改为保留句柄、请求控制器恢复，并接入轮询路径。

## 修订内容

- 通过组件依赖 override_path 使用仓库内的 Components/ThirdParty/esp_isotp，保留原始许可证和协议核心代码。
- 9 个持久 TX 槽保存描述符与数据，直到 TX-done；拒绝提交时归还，不覆写未完成传输。
- ISR 仅复制原始匹配帧到 32 项队列；任务持锁执行协议状态机、流控及完整报文提取。
- 按真实 DLC 解析帧长；输出太小时拒绝完整报文，避免截断后误判成功。
- 传感器接收缓冲采用 ISO-TP 最大容量，再严格检查 sizeof(Sensor_data_t)；用 memcpy 获取对齐结构体。
- 业务队列入队不等待，队列满时限频告警；上传取样等待使用 pdMS_TO_TICKS(100)。
- 每秒输出一次 ISOTP_DIAG；bus-off 只请求恢复，不删除仍被传输对象引用的节点。

## 验证

- 实际本地 C 适配、实际 isotp-c，加原生主机 RTOS/异步驱动替身：26/26 通过，明细见 tests.json。
- 覆盖：延迟发送的数据稳定性、槽耗尽/回收、提交失败回滚、未完成发送时禁止释放、多帧重组、真实 DLC、报文保留、错误长度拒绝、接收超时后的下一报文、RX 队列溢出计数、业务队列不阻塞、bus-off 单次恢复请求及再次恢复。
- ESP-IDF 6.0.1、ESP32-S3、新配置及强制占位凭据，完整构建与链接通过。应用镜像 0x104dd0 字节，分区剩余约 47%。编译实际使用仓库本地覆盖组件。
- 主机检查为单线程调用及模拟 ISR 边界，不是真实 FreeRTOS 多核压力测试。
- 没有烧录、双板联调、供电测量或抓取真实 CAN 波形。不能将测试通过等同为已复现并消除硬件故障。

## 上板复现步骤

1. 在已激活 ESP-IDF 6.0.1 的终端，进入实际 codex 工程目录，执行 idf.py reconfigure，然后按原串口配置 build / flash / monitor。验证目录的构建使用占位凭据，仅用于编译检查，不用于业务联调。
2. STM32 按既有 ISO-TP 配置发送传感器数据。先不开视频，保留数秒 ISOTP_DIAG。
3. 按 Key1 开始视频，保留启动前后 ISOTP_DIAG、bus-off、队列满以及驱动错误日志。
4. 记录故障后停止视频是否恢复，以及只复位哪块板时恢复。若两端均可能 bus-off，应同时检查 STM32 的错误状态与错误计数。

## ISOTP_DIAG 字段

| 字段 | 含义及判断用途 |
| --- | --- |
| state | 当前 TWAI 错误状态；枚举值以本机 esp_twai_types 定义为准 |
| TEC / REC / buserr | 发送/接收错误计数与驱动累计总线错误；恢复命令会重置驱动 buserr 历史 |
| canrx | 交给接收回调并成功读取的 CAN 帧累计数，不等于总线上全部帧数 |
| matched | 匹配当前标准数据帧 RX ID 的累计数 |
| rxdrop | ISR 原始帧队列满时的丢弃数 |
| tx_submit_fail / tx_fail | 无发送槽或驱动拒绝提交次数 / TX-done 报告失败的帧数 |
| messages | 成功提取的完整 ISO-TP 报文数 |
| pending | 等待任务处理的原始帧数量 |
| gap_max_us | 创建后记录的最大相邻轮询间隔，单位微秒；与 100000 us 的协议超时配置比较 |
| rx_state / rx_result | ISO-TP 接收状态与最近协议处理结果，按 isotp_defines.h 枚举解释 |

CAN 接收计数停止且错误计数上升时，优先核查总线、电气状态及对端。CAN 帧仍到达但完整报文停止时，结合匹配数、队列丢弃、轮询间隔和流控发送失败判断。单凭 No data to publish 无法区分这些情况。
